# longest-path — 最長片道きっぷの旅

株式会社ドリーム・アーツ 2028 年新卒エンジニア採用コーディングテストの解答です。

駅を頂点、路線を辺とする重み付きグラフで、**同じ駅を 2 度通らない最長の経路**（始点と終点が同じ閉路も可）を求めます。

## 使い方

Python 3.9 以上の標準ライブラリだけで動きます（外部パッケージ不要。3.9 / 3.10 / 3.11 / 3.12 でテスト済み）。Windows / macOS / Linux (x86_64) で同じように動きます。

```sh
# 利用できるオプションを表示
python3 -m longest_path --help

# 入力例を実行し、駅 ID を標準出力に表示
python3 -m longest_path < examples/sample.txt
```

Windows では `python3` を `py` または `python` に読み替えてください。

`-v` で総距離・探索統計を表示できます（標準エラー出力）。`-t 60` で探索を 60 秒で打ち切れます。既定は時間制限なしです。テストは `python3 -m unittest discover -s tests -t .` で実行できます。

上の入力例を実行したときの標準出力:

```
1
2
3
4
1
```

閉路 1→2→3→4→1（8.54 + 3.11 + 4 + 1.4 = 17.05）が最長です。

### 出力の約束

- **標準出力には答え（駅 ID）だけ**を出します。各行の末尾は `\r\n` です。Windows の改行変換で `\r\r\n` にならないよう、バイト列で書き出しています。
- 始点と終点が同じ閉路のときは、**始点の ID を末尾にもう一度出します**（例: `1 2 3 4 1`）。
- 出力は毎回同じになるようにそろえています。閉路は最小 ID の駅から、隣のうち ID の小さいほうへ回る向きで出します。経路は ID の小さいほうの端から出します。
- 警告（読み飛ばした行、時間切れ、中断）と `-v` の統計は標準エラー出力に出します。
- 既定では時間制限なしで、最適解が求まるまで探索します。大きな入力で終わらないときは **Ctrl+C で中断すると、それまでに見つけた最良の経路を出力して正常終了**します（終了コード 0）。

## 設計の判断

### 0. 問題の性質

最長単純路問題は NP 困難です（ハミルトン路問題を含むため）。どんな入力でも多項式時間で厳密解を出す方法は知られていません。そこで次のように方針を立てました。

- **小〜中規模では必ず最適解を出す**（分枝限定法）
- **既定では最適解が求まるまで探索する**。終わらないときは Ctrl+C（または `-t` で指定した時間制限）で打ち切ると、見つけた最良解を出す。最適と証明できていないことは標準エラー出力で知らせる
- 鉄道網の構造（分岐のない区間が大半を占める）を使って、探索する頂点の数を減らす

### 1. 話し合いで決めたこと

実装の前に、仕様があいまいな点と大きな方針を 4 つ相談して決めました。


| 論点            | 選択肢                                | 決定                         | 理由                                                                                                                        |
| ------------- | ---------------------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 実装言語          | Rust / C++ / **Python** / Go       | **Python**                 | 読みやすさと、評価者の環境構築の手軽さ（標準ライブラリだけで動く）を優先した。指数時間の探索なので Rust/C++ より扱える規模は小さくなるが、その差は言語の速さではなくアルゴリズム側の工夫（縮約・枝刈り・対称性の除去）で埋める方針にした |
| 辺の向き          | **無向** / 有向 / オプションで切替             | **無向**                     | 鉄道は上り下りどちらにも乗れる。実際の「最長片道きっぷ」も無向グラフの問題。入力の「始点・終点」は辺の両端を表すだけと解釈した                                                           |
| 大規模入力の扱い      | **厳密解＋時間制限** / 常に厳密解 / ヒューリスティック中心 | **厳密解＋時間制限**（→ 後で見直し、下記）   | 終わらないプログラムは使えない。一方で、小さい入力で最適でない答えを返すのも避けたい。時間切れのときはその時点の最良解を出し、そのことを標準エラー出力で伝える                                           |
| 時間制限の既定値（見直し） | 10 秒 / **無制限**                     | **無制限**。`-t` で付けられるようにだけ残す | 問題文には時間制限の指定がない。評価する側の環境で途中打ち切りの警告が出ると、エラーで落ちたように見えるのが良くない、という判断。終わらない場合への備えとして、Ctrl+C で中断すると途中の最良解を出して正常終了するようにした        |
| 閉路の出力形式       | **始点を末尾に再掲** / 再掲しない               | **再掲する**                   | `1 2 3 4` だと閉路なのか経路なのか出力から区別できない。`1 2 3 4 1` なら最後に戻ってくることがはっきりする                                                          |


### 2. 仕様の細かい解釈（私の判断）


| 状況                            | 扱い                                            | 理由                                                   |
| ----------------------------- | --------------------------------------------- | ---------------------------------------------------- |
| 同じ 2 駅を結ぶ辺が複数ある（平行辺）          | 別々の路線として扱う。経路では長いほうを使う。2 本使えば `A→B→A` の閉路にもなる | 同じ区間を通る別の路線は実在する。同じ線路を往復するのとは違い、2 本の別の路線なら片道の条件に反しない |
| 自己ループ `A, A, d`               | 閉路 `A→A` として候補に含める                            | 「始点と終点を同じ点にしても構わない」ので、駅を 1 つしか通らない環状線の 1 周も旅程になる     |
| 同じ辺を行って戻る `A→B→A`             | 認めない                                          | 実際には B を折り返すだけで、閉路ではない                               |
| 距離が負・NaN・無限大                  | その行を読み飛ばして警告を出す                               | 距離として意味がない。また、後述の縮約が正しいことは距離 ≥ 0 を前提にしている            |
| ID が 0 以下・整数でない、列数が違う         | その行を読み飛ばして警告を出す                               | 1 行の誤りで全体を止めるより、残りの行で答えを出すほうが役に立つと判断した               |
| 改行が `\n` だけ、タブ、空行、UTF-8 の BOM | 受け付ける                                         | 入力に対して寛容にしても困ることはない                                  |
| 入力が空                          | 何も出力せず正常終了                                    | 経路がないので、出すものがない                                      |
| 最長のものが複数ある                    | どれか 1 つ（実行するたびに同じもの）                          | 問題文に指定がない                                            |


### 3. アルゴリズム

全体の流れは **縮約 → 初期解（ヒューリスティック） → 分枝限定法** です。

#### 3.1 前処理: 次数 2 の駅をチェーンに縮約する（`network.py`）

鉄道網の駅のほとんどは「隣の駅が 2 つだけ」（次数 2）の途中駅です。分岐駅（次数が 2 でない駅、**ジャンクション**）だけを頂点として残し、その間の途中駅の連なりを 1 本の辺（**チェーン**）にまとめます。鉄道網風のテストデータでは、約 300 駅が約 30 頂点になりました。

ただし経路は「チェーンの途中で終わる」ことがあるので、単純に縮約するだけでは解を取りこぼします。距離 ≥ 0 のもとで場合を分けると、次の 3 つのどれかに当てはまります。

1. **チェーンを端から端まで通る** → 縮約後の辺としてそのまま扱える
2. **一方の端から入り、途中で終わる**（反対側の分岐駅がすでに使われている場合など）→ 反対端の 1 つ手前まで行くのが最長。これを分岐駅に付いた**しっぽ**（距離 = チェーン全長 − 最後の 1 区間）として扱う。始点側も同じ
3. **チェーンの途中から出発し、外を回って同じチェーンに戻り、途中で終わる** → チェーンを 1 区間だけ除いた形になる。これは同じ駅を通る**閉路より必ず短い**。閉路は答えとして認められているので、考えなくてよい

さらに、次数 3 以上の分岐駅から終着駅（次数 1）へ伸びる**末端チェーン**（盲腸線）は、経路の端でしか使えません。そこで探索グラフから外して、しっぽとして扱います。全駅が次数 2 の環状線だけの成分には、代表の駅を 1 つ置きます。

縮約後のグラフでは、経路は「始点のしっぽ＋ジャンクションの経路＋終点のしっぽ」の形になります。両端のしっぽには別々のチェーンを使います。

#### 3.2 初期解: 貪欲法＋局所探索（`heuristic.py`）

分枝限定法は、最初に良い暫定解があるほど早くから枝刈りが効きます。そこで、両端を貪欲に伸ばして経路を作り、次の 2 つの改善を、改善できなくなるまで繰り返します。

- **迂回の挿入**: 経路上の `a-b` を、まだ使っていない駅を通る `a-x-…-b` に置き換える（深さ 5 まで）
- **端の延長**: 端から未使用の駅へ浅く探索して伸ばす

最大 1 秒（`-t` を指定したときはその 1 割まで）を使います。乱数の種は固定しているので、結果は毎回同じです。

#### 3.3 本体: 分枝限定法（`solver.py`）

各ジャンクションを始点に深さ優先探索を行い、探索の各ノードで次の 3 つを行います。

1. 「ここで終わる経路」（両端に最良のしっぽを付ける）を候補として評価する
2. 「来たのとは別のチェーンで始点に戻る閉路」を候補として評価する
3. **上界**を計算し、暫定の最良値を超えられなければ、そこから先は探索しない

**上界の作り方**: これから使う辺の集合を F とします。F の辺の重みを両端の頂点に振り分けて合計すると、F の総距離の 2 倍になります。経路の端は F の辺を高々 1 本、まだ使っていない駅 u は高々 2 本しか持ちません。したがって

```
残りで伸ばせる距離 ≤ ( Σ_端 最も重い辺 + Σ_u 重い順に 2 本の辺の和 ) / 2 + しっぽの最大値
```

が成り立ちます。u は今いる場所から到達できる未訪問の駅だけを数えます（BFS で求める）。こうすると、行き止まりの方向や、すでに切り離された部分を自然に除けます。

**対称性の除去**: 素朴に全始点から探索すると、同じ経路を両端から 2 回見つけてしまいます。そこで各経路を、**その経路上で探索順位が最も高いジャンクション s からだけ**見つけるようにしました。

- s から前方（front）に伸ばしたあと、s の反対側（back）にも伸ばす 2 段階の探索にする（s が経路の途中にある場合を拾うため）
- s の探索を最後までやり切ったら、s をグラフから**永久に取り除く**。このため後の始点ほどグラフが小さくなる
- 同じ経路を向きを変えて 2 回数えないよう、back 側の最初のチェーン ID は front 側の最初のチェーン ID より大きいものに限る
- 分岐の多い駅から順に始点にする。早く取り除くほど、グラフが早く細かく分かれるため

**浮動小数点**: 丸め誤差で最適解を枝刈りしてしまわないよう、上界を相対 1e-12 だけ大きめに見積もります。

### 4. 正しさの確かめ方

`tests/bruteforce.py` に、縮約も枝刈りもしない素朴な総当たり解法を用意しました。ランダムに作ったグラフで本体と答えを比べています。

- 一般のランダムグラフ（平行辺・自己ループを含む）、疎なグラフ、鉄道網風グラフ（チェーン・末端チェーンを含む）
- 毎回、**ヒューリスティックありとなしの両方**で比べる。ヒューリスティックが最適解を見つけてしまうと、分枝限定法の誤りが隠れるため
- 出力された駅の並びについても、同じ駅を 2 度通らないこと、隣り合う駅の間に辺があること、距離が報告値と一致することを確かめる

単体テストでは 1,000 ケース、開発中の追加の負荷テストでは 4,500 ケースを比べ、すべて一致しました。

### 6. 限界と今後の改善案

- **より強い上界（毎回計算する形では不採用）**: 関節点で分かれる枝には経路が 1 本しか入れないことを使い、ブロックカット木で上界を鋭くする方法を、探索の各ノードで毎回計算する形で試作して計測しました。鉄道網風のグラフでは、探索ノード数が 22〜61% 減りました。ただし、探索の各ノードで関節点を求める計算（Tarjan の lowlink）が重く、1 ノードあたりの時間が約 4 倍になったため、すべてのケースで全体としては遅くなりました（例: hubs=81 で 33.6 秒 → 51.8 秒）。得をするにはノード数を 75% 以上減らす必要があり、今回は届かなかったので採用していません。ただし、これは「毎回計算する」使い方での結論です。探索の浅いところだけで計算する方法や、前処理で 1 回だけ分解して分割統治する方法は試しておらず、得をする可能性は残っています。試作のコード・計測スクリプト・結果は [`experiments/block_cut_tree/`](experiments/block_cut_tree/README.md) にあります。

- **言語**: 同じアルゴリズムを Rust や C++ に移せば、探索ノードの処理は数十倍速くなり、厳密に解ける規模も広がります。
